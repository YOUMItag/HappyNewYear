# 开发过程与复刻指南

这份文档记录本项目从"一个点子"到"可玩 Demo"的完整推进顺序，目的是让另一个人（或另一个 AI 会话）能照着复刻一款结构类似的游戏——不一定是亲戚称谓题材，也可以换成任何**有离散符号 + 有稳定关系**的题材（化学元素与反应、乐理与和弦、法律条文与判例、菜系与食材搭配）。

阅读顺序建议：先看第 0 节确定思路，再按阶段推进；每阶段末尾都有可验收的产物，做不出来就不要往下走。

---

## 0. 先想清楚"变化"落在哪一层

三消是最容易被做成换皮游戏的品类。判断你的想法是不是换皮，只问一句：**如果把美术资源全换掉，玩法会变吗？** 如果不变，那就是换皮。

本项目的变化落在**判定层**：经典三消判定"三个格子颜色相同"，本作判定"三个人之间的亲缘关系成立"。为此新增了三件事：

1. 一份有结构的数据（47 人的族谱：父母、配偶、辈分）
2. 一套判定规则（三条，覆盖 535 组合法组合）
3. 一个把关系可视化的界面（族谱面板）

**复刻时这一步最关键**：先写出一句话的规则，再验证它能否枚举出足够多的组合（至少几百组），否则盘面上根本消不动。

> 经验值：合法组合少于 200 组时，8×8 盘面的可行步数会经常低于 3，玩家会觉得"卡住"。

---

## 1. 阶段一：把规则变成数据（1~2 天）

**做什么**：写一份 JSON 数据 + 一段离线枚举，把规则从"文字描述"变成"可数的组合"。

本项目的族谱数据在 `Assets/Data/FamilyTree.json`，每人一条记录：

```json
{ "id": 12, "title": "伯父", "gen": 2, "kind": "blood",
  "fatherId": 1, "motherId": -1, "spouseId": 13 }
```

`gen` 是辈分（3 祖辈 / 2 父辈 / 1 我辈 / -1 子辈），`kind` 区分堂/表/侄/甥。

判定规则拆成三条：

| 规则 | 条件 | 实现要点 |
|---|---|---|
| R1 直系三代 | A 是 B 的父母、B 是 C 的父母 | 对每个人做「父母 × 子女」的笛卡尔积 |
| R2 同代姻亲 | 三人皆姻亲且 gen 相同 | 姻亲判定用递归：父母不在族谱内 → 本人是姻亲 |
| R3 同类三消 | 同 gen 同类 + 称谓互异 + 平辈池来自三家 | 先按 (gen, kind) 分桶，再取三元组 |

**验收标准**：脚本能打印出「R1 64 组 / R2 11 组 / R3 460 组，合计 535」。数字对不上就先别做界面。

枚举脚本建议放在 `Tools/` 下用 `dotnet` 单独跑，不要放进 Unity——它只需要读 JSON。

## 2. 阶段二：先写纯逻辑，不碰引擎（3~5 天）

**核心约定：`Assets/Scripts/Core/` 下不允许出现 `using UnityEngine;`。**

这条约束会带来一点麻烦（`Vector2`、`Debug.Log` 都不能用，要自己定义轻量结构体），但换来的是：改规则、跑 800 局仿真、写单测，全都不需要打开编辑器，一条 `dotnet test` 几秒钟出结果。

Core 层的类与职责：

| 类 | 职责 |
|---|---|
| `FamilyGraph` | 加载 JSON，建父子/配偶邻接表，预计算 535 组三元组 |
| `BoardModel` | 8×8 格子数据，交换、消除、下落、补块 |
| `MoveValidator` | 交换是否合法、是否成组、成哪条规则 |
| `ScoreKeeper` | 分组计分 × 规则倍率 × 连锁倍率 |
| `BoardGenerator` | 反向构造盘面、死局检测 |

**验收标准**：`Tools/LogicTests` 里能跑通这些用例——交换合法性、三规则各命中一次、连锁倍率封顶、消除后下落不丢块。

预计算是本项目的关键取舍：运行时的规则判定退化成一次哈希查找，代价是启动多几毫秒。对休闲游戏这笔交易划算。

## 3. 阶段三：盘面生成与数值标定（3~4 天）

### 3.1 生成算法用"反向构造"而不是"随机填充"

随机填充有两个必踩的坑：开局就可能三连（玩家一进来就看到自动消除），以及无法保证有解。

正确顺序：

1. 先摆一组"差一格就成型"的骨架，保证至少 3 步可走
2. 其余格子按"填入后不构成三连"逐格填
3. 全部填完做整体校验：无三连、可行步数 ≥ 3、同名 ≤ 2
4. 不通过就重来，超过重试上限降级为"只保证无三连"

**验收标准**：跑 150 次生成，开局自带三连比例为 0%，可走步数落在 3~9（中位 9）。

### 3.2 数值不要拍脑袋，用仿真反推

星级阈值是最容易拍错的地方。本项目第一版把三星定在 36,000，结果随机打法的最高分只有 29,975——三星根本摸不到。

正确做法：写一个模拟器，用两种打法各跑 400 局（一种随机点，一种优先找 R1），然后：

- 取混合人群的 p05 / p50 / p75 作为一/二/三星门槛
- 反复四轮，每轮看分布：0 星占比 ≤ 5%、两星以上 ≈ 50%

本项目最终：22,000 / 29,000 / 32,500，实测分布 4% / 45% / 26% / 26%。

**验收标准**：`Tools/Playtest` 能输出规则占比、分数分位、星级分布、死局频次四张表。

## 4. 阶段四：表现层与状态机（5~7 天）

**先定状态机，再写动画。** 状态机不定，动画和输入一定会交叉出 bug。

```
Idle → Selected → Swapping → Resolving → Falling → Finished
                    └─(无效交换)─→ Selected
```

规则：

- Swapping 之后所有输入屏蔽，直到回到 Idle
- 每次交换只允许一个状态，禁止"动画还在播又点了一下"
- 面板（暂停/结算/规则说明）展开时，棋盘点击由遮罩吃掉

动画实现用"步骤队列 + 时间线"：一次交换拆成若干步骤（位移、缩小、下落、淡入），每步有持续时间和插值函数，Update 逐帧推进。

### 这一层最容易出的 bug

**零时长的收尾步骤会把整盘透明度写成 0。** 本项目为了让"洗牌后整体淡入"有过渡，每次交换末尾都追加一个淡入步骤，不洗牌时时长写成 0。时间线开始播放时会先按 t=0 预演一次，于是 64 个方块透明度全被写成 0，下一帧才写回 1 —— 表现为每走一手整盘闪烁一帧。

修法两条：收尾步骤只在真洗牌时生成；淡入分支加时长守卫（时长 ≤ 0 直接 return）。

## 5. 阶段五：UI 与关系可视化（5~7 天）

族谱面板是这类游戏最难也最值钱的一块，本项目返工了三轮：

| 版本 | 问题 | 原因 | 修法 |
|---|---|---|---|
| 一 | 连线整体右移半屏 | 节点以带左上角为原点，连线层以带中心为原点 | 连线层改零尺寸，锚左上角 |
| 二 | 线对了但全是横线 | 行距只有 14 px，父子水平距离最大 1139 px，斜率 1:81 | 行高 60→70、节点高 46→40，改"竖—横—竖"折角走线 |
| 三 | 横梁糊成一根白条 | 所有家庭的横段都落在同一条行间中线 | 按左端点排序做区间着色，分车道 |

**还有一个不是连线问题的连线问题**：堂亲出自伯父、叔父两家，表亲出自姑妈、舅舅、姨妈三家。只要把"养出堂亲的家庭"排左边、"养出表亲的家庭"排右边，最长水平跨距就从 924 px 降到 457 px。

> 结论：连线难看，多半不是连线的问题，是节点没按关系排好。

**验收标准**：47 人压进 1631×300 的横条，最大跨距 < 500 px，同一缝隙的横梁不重叠。

## 6. 阶段六：把"看不见的错误"变成断言（3~5 天）

没有 GUI 验收条件时，正确性必须靠断言。本项目的三层测试：

| 层 | 手段 | 抓什么 |
|---|---|---|
| 逻辑 | `dotnet test` | 规则、计分、生成 |
| 交互 | 播放模式下模拟真实点击（15 阶段） | 输入、状态机、面板互斥 |
| 表现 | 逐帧统计 | 中间帧、可见性、高亮 |

交互自检的做法：构造 `PointerEventData`，走 `GraphicRaycaster`，从"点中格子"一路验到"重开"。15 个阶段的关键断言：

1. 射线命中 9 个采样格全部正确
2. 选中/取消，描边透明度正确
3. 无效交换回退且不计步
4. 有效交换计步、加分、HUD 同步
5. 族谱默认收起 → 点开 → 再点收起并复原盘面
6. 打开规则说明时族谱自动收起，遮罩吃掉棋盘点击
7. 动画期间点棋盘不计步
8~12. 连锁、提示、结算、星级
13. 提示只改描边，不动盘面、不吃手数
14. 自动演示中打开暂停
15. 重开后手数归零、自动演示停止

**为什么值得写**：本项目修的三处缺陷里有两条（整盘闪烁、结算后卡死）属于"状态正确但界面不可见"，纯功能测试永远发现不了。

断言形态建议写成"看图说话"的日志，一眼能看出数值对不对：

```
[CLICK] 族谱：消除后默认收起 True（盘面缩放 1.00）；点「族谱」→ 展开 True，盘面缩放 0.78；
        这一手 爷爷/伯父/堂哥 点亮 8 段；再点「族谱」→ 收起 True，盘面缩放复原 1.00
```

```bash
Unity.exe -batchmode -quit -projectPath . \
  -executeMethod Game.EditorTools.BuildScript.BuildWindowsFromCommandLine
```

## 8. 复刻检查清单

按顺序勾，任何一项不达标就别往下：

- [ ] 一句话能说清规则，且能枚举出 ≥ 200 组合法组合
- [ ] 数据是外部 JSON，不是硬编码
- [ ] Core 层零 `using UnityEngine`
- [ ] `dotnet test` 能跑通规则与计分用例
- [ ] 150 次生成：开局三连 0%、可走步数 ≥ 3
- [ ] 800 局仿真能输出星级分布，0 星 ≤ 5%
- [ ] 状态机有显式枚举，动画期间输入被屏蔽
- [ ] 面板互斥（暂停/结算/说明不会与棋盘抢点击）
- [ ] 15 阶段点击自检能一条命令跑完并给出退出码
- [ ] 逐帧断言覆盖"动画中间帧"
- [ ] 打包 0 错 0 警
- [ ] README 写清怎么跑，截图不缺

## 9. 换题材时哪些能直接复用

| 模块 | 可复用性 | 说明 |
|---|---|---|
| 盘面模型 / 交换 / 下落 / 补块 | ★★★★★ | 与题材无关，直接搬 |
| 生成器（反向构造 + 死局检测） | ★★★★★ | 只需替换"合法性判定"回调 |
| 状态机与动画时间线 | ★★★★★ | 直接搬 |
| 计分与连锁倍率 | ★★★★☆ | 倍率表按新规则重标定 |
| 关系可视化面板 | ★★★★☆ | 布局算法通用，节点内容换 |
| 族谱数据与三元组枚举 | ★★☆☆☆ | 题材专属，必须重写 |
| 数值阈值 | ★☆☆☆☆ | 必须重新仿真 |

一句话：**把"判定"抽成一个接口，其余部分就能复用到任何题材。**

## 10. 时间与工作量参考

单人（有 Unity 基础、不熟悉 UI 布局）：

| 阶段 | 工作量 |
|---|---|
| 规则与数据枚举 | 1~2 天 |
